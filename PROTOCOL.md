# Протокол эксперимента

Основные вычисления выполняются в Kaggle CPU Notebook. Измеренные результаты и окружение сохраняются в evidence/.

1. Kaggle CPU Notebook читает реальные пять файлов. Сначала аудит типов, пропусков, единиц start/stop/duration, границ временных окон и дублей. Точное начало hold-out выбирается по реальному расписанию 21–30; training только до этой границы. Конец проверки ограничен тренировочными неделями. Времена просмотра, пересекающие границу, обрезаются до join.
2. Join по каналу и пересечению полуоткрытых интервалов. Сопоставляются все пересечения, включая перекрывающиеся эфиры. Неразмеченный id=0 не является объектом. Дубли/перекрытия просмотра одного эфира объединяются до применения порога. Абсолютный порог фиксируется после описательной статистики, до сравнения моделей; не подбирается под Kaggle score. Подсчитывается покрытие по строкам и секундам, с явными знаменателями.
3. Когорта фиксирована идентификаторами реального submission.csv; тренировочные пользователи вне неё могут помогать collaborative filtering. MAP@5 усредняется по всей фиксированной когорте; пустой набор релевантных объектов даёт AP=0. Дополнительно диагностически показываются MAP среди активных и число пустых пользователей. Нельзя подменять основную метрику метрикой активной подгруппы.
4. AP@5 = sum(P@r * hit_r, r=1..5) / min(5, |R_u|); AP=0 при пустом R_u. Ground truth — уникальные размеченные передачи, прошедшие порог в validation. Повтор уже просмотренной передачи разрешён. Кандидаты — ненулевые id в расписании прогнозируемого окна. Для будущего расписания используются только допустимость и эфирные интервалы; атрибуты content модели берутся из прошлого.
5. Popularity: число уникальных тренировочных зрителей. Content: TF-IDF по field-qualified category/genres/year/director/actors, логарифмические веса по числу эфиров, нормализованный профиль, cosine. Implicit ALS: c_ui=1+20*log(1+n_ui), 32 фактора, regularization=.1, 20 итераций, seed=2026, 2 threads. Итерация меняет ТОЛЬКО число факторов 32 -> 64. Конфигурации зафиксированы в run manifest. ALS реализован точным решением взвешенных нормальных уравнений на NumPy/Numba.
6. Все методы ранжируют одинаковые кандидаты. Слоты без положительного модельного сигнала заполняются popularity; ties: popularity, затем id. Для cold-start полностью popularity. Валидационные преобразования обучаются только на тренировочной части. Test views не существуют в используемом пайплайне.
7. Примеры выбираются по активности в train и наличию проверяемых validation просмотров, а не по выгодному исходу конкретного метода. Один более активный и один менее активный пользователь; показываются все методы на этих же двух ID. Новизна означает отсутствие в наблюдаемой истории этой платформы, а не «никогда не смотрел».
8. Выбор конфигурации — по одному hold-out. После выбора refit всей разрешённой истории. Проверка CSV: настоящий заголовок, ровно пользователи и порядок шаблона, по пять различных ненулевых допустимых id. Сохраняются SHA-256, Kaggle run/version, параметры, wall-time, версии и аппаратное окружение.
9. Финальный CSV отправляется один раз после проверки. COMPLETE, reference ID, private score фиксируются; screenshot снимается с интерфейса. Leaderboard position не используется. Репозиторий содержит код, ноутбук, зависимости, воспроизведение, именно отправленный CSV; без сырых данных и секрета.
10. Личная проверка — отдельный блок после реальных результатов: расчёт AP@5 студенткой, объяснение предположения/альтернативы, собственный вывод и улучшение. Не подменяется агентскими unit tests.

## Проверка времени

В тренировочной истории обнаружен скачок шкалы часов на 3600 с 2020-03-29. Для просмотров и расписания timestamps начиная с 04:00 переводятся на непрерывную относительную ось вычитанием 3600 с; абсолютный часовой пояс не утверждается. После преобразования проверяется duraton = end − start для всех строк. Числа исходных и оставшихся расхождений сохраняются в coverage.json. В отчёте даты возвращаются к исходной шкале файлов.
